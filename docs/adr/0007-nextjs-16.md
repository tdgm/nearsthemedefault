# ADR 0007 - Next.js 16 em vez do 15 fixado no CLAUDE.md

- Status: aceito
- Data: 2026-11-04

## Contexto

`CLAUDE.md` fixava **Next.js 15 (App Router)** como stack obrigatoria,
escrito antes do Next 16 existir. Como a Fase 0 ainda nao tinha nenhuma
linha de app criada, a escolha entre 15 e 16 nao e migracao - e so decidir
onde nascer. Por ser uma instrucao escrita explicita do usuario (nao um
ponto ambiguo qualquer), a troca foi levada para decisao dele em vez de
resolvida pela regra do proprio CLAUDE.md de "escolha a mais conservadora e
siga".

Pontos levantados a partir do guia oficial de migracao
(nextjs.org/docs/app/guides/upgrading/version-16):

- Turbopack estavel por padrao no `dev`/`build` no 16; no 15 ainda nao era
  o default.
- `next build` no 16 remove as metricas de tamanho do output (o proprio
  Next considera isso impreciso para arquitetura RSC e recomenda
  Lighthouse/RUM em vez disso) - o que de qualquer forma ja era a nossa
  estrategia: `scripts/check-budgets.mjs` le `.next/app-build-manifest.json`,
  nunca o print do `next build`.
- `next lint` foi removido no 16 - ja e como o `ci.yml` roda hoje
  (`pnpm lint` separado, nao `next lint`).
- Cache API estavel sem prefixo `unstable_` (`updateTag`, `refresh`).
- Node >= 20.9 e TypeScript >= 5.1 passam a ser minimo - ja cobertos pelo
  `NODE_VERSION: "22"` que o `ci.yml` ja usava.
- **Troca real, nao so de nome**: `nears.config.yaml > rendering.partialPrerender`
  (pensado para a PPR experimental do 15) nao existe mais no 16. O
  substituto e o modelo Cache Components (`cacheComponents: true`), mais
  estrito: builda com erro se achar dado dinamico fora de um `Suspense`.
  Isso e disciplina boa para CWV (forca streaming boundary explicito), mas
  e uma troca de modelo de cache, nao so de flag.

## Decisao

**Next.js 16**, confirmada pelo usuario em 2026-11-04.

Mudancas feitas junto com este ADR:
- `CLAUDE.md > Stack obrigatoria`: "Next.js 15" -> "Next.js 16".
- `nears/nears.config.yaml > rendering`: `partialPrerender: true` ->
  `cacheComponents: true`.
- `docs/ROADMAP.md > Fase 0`: "Next 15 App Router" -> "Next 16 App Router".
- `docs/PROMPTS.md`: nenhuma mudanca necessaria (o Kickoff nao fixa numero
  de versao, so "Next.js App Router").

Quando a Fase 0 for implementada, `apps/web/next.config.ts` declara
`cacheComponents: true` e Turbopack sem config extra (ja e o default).

## Consequencias

- Toda pagina criada a partir da Fase 5/6 em diante precisa envolver leitura
  de dado dinamico em `Suspense` desde o primeiro componente - nao e algo
  para "ajustar depois". Vale revisitar o prompt de Fase 6 em
  `docs/PROMPTS.md` quando chegarmos la, caso essa disciplina precise de uma
  frase explicita.
- Nenhuma dependencia ja escolhida neste repo (Radix, Zod, Vitest,
  Playwright, Storybook) tem incompatibilidade conhecida com Next 16 /
  React 19.2 no momento desta decisao.
- `eslint-config-next` passa a usar flat config por padrao no 16 - o
  `eslint.config.mjs` da Fase 0 ja nasce no formato novo, sem config legada
  pra migrar depois.

## Verificacao

Resumo das breaking changes conferido na documentacao oficial
(`nextjs.org/docs/app/guides/upgrading/version-16`) antes da pergunta ao
usuario, cobrindo: versao minima de Node/TypeScript, Turbopack, Async
Request APIs, cache (`cacheComponents`, `updateTag`, `refresh`), remocao de
PPR experimental, renomeacao de `middleware` para `proxy` (edge runtime
continua exigindo `middleware`), mudancas de `next/image` (quality/cache
defaults, `localPatterns`), rotas paralelas exigindo `default.js`, e
remocao de `next lint`/AMP/`serverRuntimeConfig`.
